> 📅 **최종 확인**: 2026-11-22

LLM에게 "문서에서 정보를 뽑아 줘"라고만 하면 매번 다른 이름, 다른 형식으로 답합니다. 온톨로지가 있으면 **어떤 유형의 개체와 어떤 관계를 뽑을지**를 정확히 알려 줄 수 있습니다. 이를 **스키마 기반 추출**이라고 합니다.

## 요약

- 온톨로지의 클래스·관계 목록을 **프롬프트에 자동으로 넣어** 추출 범위를 정합니다.
- 결과가 항상 같은 형식으로 나오므로 **바로 지식그래프에 넣고 검증**할 수 있습니다.
- 온톨로지가 바뀌면 프롬프트도 **자동으로** 바뀝니다. 손으로 고칠 필요가 없습니다.

## 스키마 없는 추출 vs 스키마 기반 추출

| | 스키마 없이 | 스키마 기반 |
|---|---|---|
| 관계 이름 | "납품", "공급 계약", "제공함" 등 제각각 | 항상 "공급한다" |
| 출력 형식 | 문장, 목록, 표가 섞임 | 정해진 JSON |
| 검증 | 사람이 읽고 판단 | 코드로 자동 검사 |
| 온톨로지 반영 | 수작업 변환 | 바로 반영 |

## 코드: 온톨로지에서 프롬프트 만들기

온톨로지 파일(`company.ttl`)에서 클래스와 관계를 읽어 추출 프롬프트를 자동으로 만듭니다. 전체 코드는 `code/07_schema_prompt.py`입니다.

```python
from rdflib import OWL, RDF, RDFS
from common import load, label

g = load()
classes = sorted(label(g, c) for c in g.subjects(RDF.type, OWL.Class))
relations = [
    f"- {label(g, p)}: {label(g, g.value(p, RDFS.domain))} → {label(g, g.value(p, RDFS.range))}"
    for p in g.subjects(RDF.type, OWL.ObjectProperty)
]
```

**실행 결과 (만들어진 프롬프트)**

```text
다음 문서에서 사실을 추출해 JSON으로만 답해 줘.

[허용하는 개체 유형]
사람, 산업, 제품, 조직, 직원, 회사

[허용하는 관계] (주어 유형 → 목적어 유형)
- 경쟁한다: 회사 → 회사
- 공급한다: 회사 → 회사
- 근무한다: 사람 → 회사
- 만든다: 회사 → 제품
- 속한 산업: 회사 → 산업

[규칙]
1. 위 목록에 없는 관계는 만들지 마.
2. 각 사실마다 근거가 된 문장을 원문 그대로 evidence 에 넣어.
3. 문서에 없는 내용은 추측하지 마.

[출력 형식]
{"triples": [{"subject": "", "relation": "", "object": "", "evidence": ""}]}

[문서]
{문서}
```

`{문서}` 자리에 분석할 문서를 넣어 LLM에 보내면 됩니다. 결과는 04-2의 검증 코드로 바로 검사할 수 있습니다.

[[TIP("요령: 구조화된 출력 기능 함께 쓰기")]]

많은 LLM API가 답을 **정해진 JSON 형식(JSON 스키마)으로만** 내도록 강제하는 기능을 제공합니다. 온톨로지에서 만든 관계 목록을 JSON 스키마의 허용 값(enum)으로 넣으면, 목록에 없는 관계가 나올 가능성을 더 줄일 수 있습니다. 기능 이름과 사용법은 각 서비스의 공식 문서를 확인하세요.

[[/TIP]]

## 관계 설명 덧붙이기

관계 이름만으로 헷갈리는 경우 `rdfs:comment`에 설명을 적고 프롬프트에 함께 넣습니다.

```turtle
ex:suppliesTo rdfs:comment "주어 회사가 목적어 회사에 부품·소재·제품을 판매한다. 단순 업무 협약은 해당하지 않는다."@ko .
```

이런 설명은 "업무 협약"을 "공급"으로 잘못 뽑는 실수를 줄여 줍니다.
