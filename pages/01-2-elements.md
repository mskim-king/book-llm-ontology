온톨로지를 만들 때 쓰는 기본 재료는 네 가지입니다. 이 네 가지만 이해하면 어떤 온톨로지를 봐도 구조를 읽을 수 있습니다.

## 요약

- **클래스**: 개념의 종류 (예: 사람, 회사)
- **인스턴스**: 클래스에 속한 실제 대상 (예: 김철수, A전자)
- **속성**: 대상의 특징이나 대상 사이의 관계 (예: 이름, 근무한다)
- **제약·규칙**: 지켜야 할 조건 (예: 사람은 생년월일을 하나만 가진다)

## 네 가지 구성 요소

| 요소 | 설명 | 예시 |
|---|---|---|
| 클래스(Class) | 같은 성질을 가진 대상들의 묶음 | 사람, 회사, 직원, 산업 |
| 인스턴스(Instance) | 클래스에 속한 하나하나의 대상 | 김철수(사람), A전자(회사) |
| 속성(Property) | 데이터 속성: 값을 가짐 / 객체 속성: 다른 대상과 연결 | 데이터: 설립연도 = 1990 / 객체: 김철수 —근무한다→ A전자 |
| 제약·규칙(Axiom) | 반드시 지켜야 할 조건이나 추론 규칙 | 직원은 사람의 하위 클래스, 근무한다의 주어는 사람 |

## 예시: 작은 회사 온톨로지

```text
[클래스 계층]
사람
 └─ 직원
회사

[속성]
근무한다: 사람 → 회사        (객체 속성)
설립연도: 회사 → 숫자         (데이터 속성)

[인스턴스와 사실]
김철수 ─유형→ 직원
A전자  ─유형→ 회사
김철수 ─근무한다→ A전자
A전자  ─설립연도→ 1990
```

이 정의가 있으면 컴퓨터는 다음을 알 수 있습니다.

- 김철수는 **직원**이므로 **사람**이기도 하다. (클래스 계층에 따른 추론)
- "근무한다"의 목적어는 **회사**여야 하므로, "김철수 —근무한다→ 서울"은 잘못된 데이터다. (제약 검사)

[[TIP("요령: 이름 짓기 규칙")]]

클래스는 **단수 명사**(사람, 회사), 관계는 **동사구**(근무한다, 속한다)로 이름을 지으면 읽기 쉽습니다. 한 온톨로지 안에서는 같은 규칙을 일관되게 지킵니다.

[[/TIP]]

## 설계할 때 자주 하는 실수

| 실수 | 예 | 바로잡기 |
|---|---|---|
| 클래스와 인스턴스 혼동 | "A전자"를 클래스로 만듦 | A전자는 "회사" 클래스의 인스턴스 |
| 관계를 클래스로 만듦 | "근무" 클래스를 만듦 | "근무한다"라는 속성으로 표현 |
| 너무 깊은 계층 | 사람 → 성인 → 직장인 → 정규직 → … | 실제로 구분이 필요한 단계만 남김 |
