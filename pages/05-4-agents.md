> 📅 **최종 확인**: 2026-11-22

AI 에이전트는 목표를 받으면 스스로 계획을 세우고 도구를 사용해 여러 단계의 일을 처리합니다. 에이전트에게 지식그래프를 **도구**로 주면, 필요할 때 정확한 사실을 조회하고 그 결과를 근거로 다음 행동을 정할 수 있습니다.

## 요약

- 지식그래프를 에이전트의 **조회 도구**로 제공합니다 (예: "공급망 조회", "회사 정보 조회").
- 에이전트는 질문을 풀기 위해 **여러 번 조회**하며 답을 만들어 갑니다.
- 온톨로지는 에이전트가 **어떤 정보를 물어볼 수 있는지** 알려 주는 지도 역할을 합니다.

## 에이전트에게 줄 도구 설계

자유로운 SPARQL을 맡기기보다, **목적이 분명한 작은 도구**를 여러 개 주는 편이 안전합니다.

| 도구 이름 | 입력 | 출력 | 내부 동작 |
|---|---|---|---|
| `find_company` | 회사 이름(동의어 포함) | 회사 ID, 공식 이름 | label·altLabel 검색 |
| `get_suppliers` | 회사 ID, 단계 수 | 공급사 목록과 단계 | SPARQL `ex:suppliesTo+` |
| `get_competitors` | 회사 ID | 경쟁사 목록 | 대칭 관계 조회 |
| `get_company_info` | 회사 ID | 산업·설립연도·제품 | 속성 조회 |

## 동작 예시

**요청:** "A전자 공급망 중에서 경쟁사와도 거래하는 곳이 있는지 확인하고, 위험 요약을 써 줘."

```text
[생각] A전자의 ID부터 찾아야 한다.
[도구] find_company("A전자")        → ex:AElec
[도구] get_suppliers(ex:AElec, 2)   → B소재(1단계), D화학(2단계)
[도구] get_competitors(ex:AElec)    → C전자
[생각] 공급사들이 C전자에도 공급하는지 확인해야 한다.
[도구] get_suppliers(ex:CElec, 1)   → D화학
[생각] D화학이 양쪽 공급망에 모두 있다.
[답변] A전자의 2단계 공급사인 D화학은 경쟁사 C전자에도 직접 공급합니다.
       D화학에 문제가 생기면 A전자와 C전자가 동시에 영향을 받을 수 있습니다.
```

위 흐름은 03-2의 SPARQL 결과(④, ⑤)와 같은 데이터를 바탕으로 한 **설명용 예시**입니다. 실제 에이전트의 생각과 도구 호출 순서는 모델과 설정에 따라 달라집니다.

[[TIP("알아두기: MCP")]]

MCP(Model Context Protocol)는 AI 애플리케이션이 외부 도구·데이터와 연결하는 방식을 표준화한 프로토콜입니다. 지식그래프 조회 기능을 MCP 서버로 만들어 두면, MCP를 지원하는 여러 AI 도구에서 같은 지식그래프를 쓸 수 있습니다.

[[/TIP]]

## 안전하게 운영하기

| 위험 | 대책 |
|---|---|
| 에이전트가 지식그래프를 수정 | 조회 도구만 제공, 수정은 사람 승인 절차(04-4)로 |
| 너무 긴 탐색으로 비용·시간 증가 | 탐색 단계 수와 도구 호출 횟수 제한 |
| 민감한 정보 노출 | 도구마다 접근 가능한 데이터 범위 제한 |
| 틀린 결론 | 답변에 사용한 도구 호출 결과를 함께 기록 |

## 실무 체크포인트

- [ ] 목적이 분명한 작은 조회 도구로 나눴는가
- [ ] 에이전트에게는 조회 권한만 주었는가
- [ ] 도구 호출 횟수와 탐색 깊이를 제한했는가
- [ ] 답변의 근거가 된 도구 호출 기록을 남기는가
